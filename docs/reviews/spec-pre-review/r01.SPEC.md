- `scripts/240_verify_shards.py`（只作异常指示，见 A-13）

**必需材料**：本项范围内全部文件；`slurm/isref_all/V2_verified.sh`（A-1、A-3、A-10 依赖其命名与 verified JSON 格式）。

**目的**：用现有证据给遗留的 outfmt 6 shard 分类。**永不得出"完整"的结论**：outfmt 6 不报告零命中查询，因此证明不了每条查询都被处理过。

### 定义
- N = 63,095。`idx(q)` 为查询 q 在 `all_queries.fna` 中的 0 起位置（= `query_ids.txt` 的行序）。
- H(s)：shard s 的过滤后命中文件中，至少出现一行的查询 id 集合。
- M(s) = max{ idx(q) : q ∈ H(s) }。
- 参考 shard：证据可读、与当前文件身份绑定（A-2），且未被判为 TRUNCATED 的 shard。
- R = 在 ≥ 90% 参考 shard 中都出现于 H 的查询集合。p_r 为 r 在参考 shard 中的出现率。
- T(s) = |{ r ∈ R : idx(r) > M(s) }|。
- B(s) = R 中满足 idx ≤ M(s) 的成员里，不在 H(s) 中的比例（已读部分中缺失的参考查询所占比例）。

### 验收标准

**A-1 判词表封闭。**
- 判词只能是 `TRUNCATED`、`CORRUPT`、`ANOMALOUS`、`NOT_AUDITED`、`UNVERIFIABLE_CONSISTENT` 之一。
- 241 的源码和输出中，不得把 `complete`、`COMPLETE`、`OK`、`verified` 作为遗留 shard 的结论。
- 经 V2 验证的 shard 列为"不在审计范围"，并注明来源 `v2/verify/verified_<i>.json`。241 不给它们判词。

**A-2 证据与文件身份绑定。**
- V1 为每个 shard 记录命中 gz 与 copies 文件的大小、mtime，以及命中 gz 的 sha256。
- 241 运行时重新核对；任一不符 → `NOT_AUDITED`。
- 证据文件先写临时名再 `mv`。读取失败时不得留下证据文件，从而杜绝沿用上一轮的陈旧证据。

**A-3 文件命名不冲突。**
- V1 的命中证据命名为 `hitq_<i>.txt`，内容是有命中的查询。
- V2 的宣告列表命名为 `announced_<i>.txt`，放在 v2 命名空间下，内容是全部宣告的查询。
- 241 只读 `hitq_*`。把宣告列表当作命中证据，会让"每条查询都命中"混进 R。

**A-4 CORRUPT。** copies 文件无法完整读取，或 `zcat` 返回非零（含 CRC 失败），判 `CORRUPT`。不得判为可读。

**A-5 NOT_AUDITED。** 没有 done marker、没有证据、或证据陈旧，判 `NOT_AUDITED`。不得并入 consistent。

**A-6 截断判定（预注册）。** `TRUNCATED` 当且仅当 T(s) ≥ 5。

推导：
- 在 H0（完整读取）下，R 中位于 M(s) 之上的成员，正好是 R 按 idx 排序后的一段后缀。因此 T(s) ≥ k 意味着 R 中 idx 最大的 k 个成员在 s 中**全部缺席**。
- 每个 r ∈ R 都有 p_r ≥ 0.90，故 P(T ≥ 5 | H0) ≤ ∏(1 − p_r) ≤ 0.1⁵ = 10⁻⁵（每个 shard）。64 个 shard 的族错误率 ≤ 6.4×10⁻⁴。
- 前提：同一 shard 内各查询的缺席相互独立。输出中须声明这一前提。

241 须对每个 shard 报告：T(s)、M(s)/N，以及按经验 p_r 计算的 R 中最后 5 个成员的 ∏(1 − p_r)。

注意：判定**不得**要求"所有缺失的 R 成员都在 M(s) 之上"。被截断的 shard 在已读部分中，同样会有正常缺席的 R 成员（R 允许每个成员最多 10% 缺席），这样的规则几乎永远不会成立。

**A-7 ANOMALOUS（预注册）。** 未判 `TRUNCATED`，且 B(s) > median(B) + 5 × max(MAD(B), 0.001)，其中 median 和 MAD 在参考 shard 上计算。

来源：常规稳健离群规则，未经校准。固定 2% 这类没有来源的阈值不允许使用。须同时输出 B 的观测分布。

**A-8 UNVERIFIABLE_CONSISTENT。** 证据可读，且不是 `TRUNCATED` 或 `ANOMALOUS`。输出须写明"outfmt 6 无法证明完整"。

**A-9 R 的有效性（审计前提）。** 下面任一条不满足，审计中止：以非零状态退出，不写任何判词文件，也不写部分判词。
- (a) R 迭代构建：每轮剔除 `TRUNCATED` 后重算，直至判词集合稳定，最多 5 轮；
- (b) 把 idx 按十分位划分，R 在每个十分位的密度 ≥ 各十分位平均密度的 50%；
- (c) 参考 shard 数 ≥ 20。

来源：截断检验要求 R 在查询文件尾部也有成员。50% 与 20 为预注册值。

背景：查询文件按 `seq_key`（哈希）排序，63,095 条中有 61,493 段 bag 连续段，即文件位置与 bag 近似无关。

**A-10 R 的组成。** 经 V2 验证的 shard，其命中集合（同为 ≥200 bp 过滤后的语义）可计入 R，但不得到判词。

**A-11 重做清单** = TRUNCATED ∪ CORRUPT ∪ ANOMALOUS ∪ NOT_AUDITED。`UNVERIFIABLE_CONSISTENT` 不进重做清单，但其标签必须向下游传递（见 S-1）。

**A-12 判词文件。**
- 原子写出（临时名 + `mv`）；
- 包含 G-3 字段、全部输入的 sha256、参数（0.90、5、5×MAD、0.001、50%、20）、|R|、迭代轮数，以及每个 shard 的全部判定量。

**A-13 240 仅作异常指示。**
- 标签只能是 `IN_BAND` / `BELOW_BAND`，不得出现 `OK`；
- docstring 不得声称"验证"；
- 不写下游会消费的任何 marker 或判词。

下限 0.80 × 中位数为预注册值，只用于指示。

**A-14 测试（合成 shard，登录节点小样本）。**
- (a) 在 34% 处前缀截断、且已读部分有正常缺席 → `TRUNCATED`；
- (b) 完整读取、随机缺席 5% → `UNVERIFIABLE_CONSISTENT`；
- (c) 全程散布缺席 30% → `ANOMALOUS`；
- (d) gz CRC 损坏 → `CORRUPT`；
- (e) 证据与文件身份不符 → `NOT_AUDITED`；
- (f) R 缺少最后一个十分位 → 审计中止；
- (g) 输出中不出现 A-1 禁用的词。

## 项 3：242 位点合并

审查命令：`codex-review "242 位点合并" review-hard`

**范围**
- `scripts/242_collapse_sites.py`
- 驱动作业（待写）
- 测试（待写）

**必需材料**：本项范围内全部文件；`scripts/239_chain_copies.py`（输入格式与坐标来源，S-3、G-2）；`scripts/233_isref_copies.py`（S-5 阈值来源）；`slurm/isref_v1/loci.sh`（S-11）；`scripts/241_audit_shards.py`（S-1 门控所用判词格式）。

**目的**：把 copies 合并为 sites，即跨查询去重。输出是**候选位点**，既未经验证（验证属 Stage E：侧翼 / ISCompare），也不是 events。

### 验收标准

**S-1 输入门控与标签传递。**
- shard i 只有满足以下之一才被消费：
  - v2 done marker 存在且 `verified: true`；或
  - 遗留 done marker 存在，且 241 对**当前文件身份**的判词为 `UNVERIFIABLE_CONSISTENT`。
- 每条位点记录携带 `shard_id` 和 `shard_status`（取值 `VERIFIED_V2` / `UNVERIFIABLE_CONSISTENT`）。
- 未被消费的 shard 连同原因写入元数据。
- 位点总数按 `shard_status` 分开报告。

**S-2 "shard 间基因组不相交"前提必须被检查，而不是假设。**
- (a) 一次性检查 64 份清单两两不相交、并集 = 40,541，否则致命；
- (b) 每条数据行的 assembly 必须属于该 shard 的清单，否则致命；
- (c) 已消费的 shard 输出之间，同一 assembly 不得出现在两个 shard 中。

只有在这个前提成立时，"按 shard 独立合并即全局精确"才成立，因为一个位点的所有 copies 都在同一个 shard 文件里。

**S-3 输入格式严格。**
- 首行必须逐字等于 239 的 16 列表头：`query_id bag_id assembly species contig s0 s1 strand n_hsp qcov pident copy_kind catalogue_status catalogue_occurrence catalogue_bag same_bag`。缺失或不符，致命。
- 任何字段数 ≠ 16、s0/s1 不是整数、或 `s1 − s0 ≤ 0` 的行，致命。

copies 文件由机器写出，畸形行意味着截断或损坏，不得"跳过并计数"。

**S-4 分组检查。** 同一 (assembly, contig) 的行必须连续出现。某个键在其分组被处理之后再次出现，致命。组内不要求按 s0 排序。

**S-5 合并规则（双向）。**
- copy b 并入种子 a，当且仅当 `ov/len(a) ≥ 0.50` **且** `ov/len(b) ≥ 0.50`，其中 `ov = min(a1, b1) − max(a0, b0)`，区间按 G-2；
- 只在同一 (assembly, contig) 内合并；
- 合并与链方向无关，须在输出中写明。

来源：与 239/233 判定"已编入目录"的 `--recip 0.50` 形式与数值相同，使位点之间、位点与目录之间用同一条重叠规则。未经校准。

不用单向规则（按较短者计重叠）的原因：一个 1.3 kb 的 IS 位于 5 kb 的复合转座子内部，覆盖 IS 的 100%，只覆盖转座子的 26%；单向规则会把两个不同结构合成一个位点。

**S-6 贪心顺序完全确定。**
- 种子按（长度降序、s0 升序、s1 升序、query_id 升序）排序；
- 代表 copy 按（qcov 降序、pident 降序、长度降序、query_id 升序）选取；
- 主链方向平票时取 `+`。

输出不得依赖组内输入行序。测试：打乱行序后输出逐字节相同。

**S-7 不做传递合并。**
- 成员资格只与种子区间比较；种子区间不因吸收成员而扩张；
- 输出分别给出种子坐标（`seed_s0, seed_s1`）和成员包络（`env_s0, env_s1`）。

**S-8 复杂度。**
- 候选只在与种子重叠的 copies 中搜索（区间索引，或排序后二分查找），不得对每个 contig 做全两两比较；
- 验收：行数最多的已消费 shard 在单个 cf1 节点上 4 小时内完成（预注册预算）。

背景：遗留 shard 平均约 4,900 万个 copies，约每基因组 7.9 万个。完整基因组的大部分 copies 落在一条染色体 contig 上。

**S-9 计数恒等。** 各位点 `n_copies` 之和 = 读入的数据行数。不等则致命。该等式写入元数据。

**S-10 嵌套与片段必须被度量，不得隐藏。** 报告以下两项：
- (a) 种子区间完全落在同一 contig 上另一位点种子区间之内的位点数。这是双向规则的直接后果：例如 300 bp 的片段命中落在 1.3 kb 全长拷贝之内，ov/len(全长) = 0.23，会单独成为一个位点；
- (b) 代表 copy 的 copy_kind 为 fragment、partial 的位点数。

**S-11 与旧 loci 数字可比。** 在同一输入上，另报按旧规则 `isref_v1/jobs/loci.sh` 得到的计数，规则如下：
- 只取 `full_copy`；
- 按 s0 排序；
- 当 `s0 < ce − 50` 时合并，且 `ce = max(ce, s1)`（单向、传递）。

来源：该规则产出了 181 条查询扫描的 790,174 个 loci。凡与 790,174 作比较，都必须用这个旧规则的计数，不得用 242 的位点数。

**S-12 判词表。**
- `catalogue_status` 取值只能是 `catalogued` 或 `not_in_catalogue`；
- 位点只要有至少一个成员 copy 被 239 判为 catalogued，就是 `catalogued`；
- 242 的输出不得出现 "validated" 或 "new site"。

**S-13 已知限制必须声明。** 环状 contig 上跨原点的拷贝会被拆成两个位点（239 不携带 contig 长度，本项不处理）。元数据的 `limitations` 字段须列出这一条。

**S-14 元数据 JSON**（原子写出）：G-3 字段、输入路径/大小/sha256、参数、计数（含 S-9、S-10、S-11）、`limitations`、未消费 shard 及原因。

**S-15 测试（小样本 fixture，登录节点）。**
- (a) 1.3 kb 位于 5 kb 之内 → 两个位点；
- (b) 两个近同拷贝 → 一个位点；
- (c) A–B、B–C 各自双向 ≥ 0.5，但 A–C < 0.5 → A 与 C 不得经 B 传递合并；
- (d) 打乱行序 → 输出相同；
- (e) 缺表头 → 致命；
- (f) 键重现 → 致命；
- (g) 畸形行 → 致命；
- (h) assembly 不在清单 → 致命；
- (i) 计数恒等成立。
