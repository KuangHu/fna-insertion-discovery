## 需要知道的限制

1. **加深部分不是随机样本。** 驱动脚本按 `ls` 的顺序（即种子 accession 的字母序）把 panel 交给 `xargs -P 4`，所以完成的恰好是字母序最前的那一段。核对结果：4 个超时物种中，完成的 panel 正是排名 0 到 N−1 的连续前缀，E. coli 为 0–559，最后一个是 `GCA_029719025.1`。也就是说，加深部分偏向较早提交的 GCA 组装。`xrun_four.sh` 的注释说增量是"该设计所能带来的样本"，但这个样本有偏，**不能按完成比例外推**全量加深的收益。
2. **代码版本不能逐字节确认。** v3 是 9-25 用当时**未提交的工作区**构建的，其中已包含 9-25 发现的 run 作用域 id 修复（`lib_insert.panel_label`）。这个修复到 10-05 才在 `4674c79` 中提交，同一提交还改动了 `100`、`99`、`86`。v3 的 locus id 确实带 `full_<sp>/…`、`deep_<sp>/…` 前缀（E. coli：full 41,607 个、deep 38,713 个），与修复后的代码一致，但当时运行的确切代码没有记录。
3. **`catalogue_deep/` 已作废。** S. pneumoniae 加深运行在步骤 1 自动产出的 `catalogue_deep/spneumoniae` 是在 id 修复之前合并的：两轮共有 143 个同名 panel，部分 locus 被静默覆盖（见 `lib_insert.panel_label` 的说明）。应以 v3 为准。
4. **每个物种的 panel 数量不同**：第一轮 200 或 400，加深轮按完成情况而定。跨物种比较事件数时，这一点和基因组数一样，是混杂因素。
5. **`sa_k12` 与 `sa_k24` 是同一物种。** database_v3 剔除了 `sa_k12`，insertions_all 保留了它。按物种汇总 insertions_all 时，S. aureus 可能被重复计数。
