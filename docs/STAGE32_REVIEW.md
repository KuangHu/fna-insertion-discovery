## 有可信信号

- E. coli 有 8 行、K. pneumoniae 有 6 行：插入长度 777 bp，接合处的直接重复为 9 bp。这正是 IS1（768 bp）加 9 bp TSD 的典型特征，与 README 中 Arm B 单独测得的"777 bp 插入带 9 bp TSD"一致。也就是说，大岛内部的 IS1 插入确实能被找到。
- 带 2–15 bp 直接重复（类 TSD）的行：E. coli 10/26，K. pneumoniae 19/53。

## 方法上的问题

1. **只比较长度相差不到 1 kb 的岛对。** 父岛先按 `parent_len // 1000` 分桶，只在同一桶内配对，所以两个父岛长度差 d 恒小于 1,000 bp；跨越千位边界的岛对（例如 7,950 与 8,050）也不会被比较。结果是长度约 1 kb 以上的干净嵌套插入**原理上找不到**，而常见 IS 正好落在这个范围：IS110 为 1,279 bp，IS3、IS5 家族约 1.2–1.5 kb。脚本的设计范围是 500–5,000 bp，与实际行为不符。
2. **长度 ≥1 kb 的候选必然不是干净插入。** 因为 d < 1 kb，所以 `nested_len − d` 就是短等位上被替换掉的碱基数。nested_len ≥ 1,000 的行（E. coli 11/26，K. pneumoniae 33/53）一定伴有靶位丢失，属于"替换"，与主目录"插入"的定义不同。
3. **不比较反向的岛对。** 分解时直接比较原始序列，没有尝试反向互补；方向相反的同一岛会被漏掉。
4. **只做精确前后缀匹配。** 一个 SNP 就会截断匹配。Layer 2 早已因为同样的原因加入了容错分解。
5. **insert key 与 junction 位置有关。** 上面 8 个 IS1 样行的 key 互不相同，因为切出的插入序列随位点带上不同的 TSD 拷贝。主目录早已改用 `lib_insert.canonical_insert_key()`（在重复区内滑动取最小键）。因此"不同 insert key 数"高估了不同元件数，与主目录的合并率则被低估。
6. **合并率的参照已经过时。** 当时对照的是审查修复之前的 v1 目录（E. coli 21,051、K. pneumoniae 11,794 个事件），使用旧的键定义。"新增 23 / 48"对 v3 不成立。
7. **输出只有哈希。** 没有插入序列、靶位序列和基因组坐标（offset 是岛内坐标），无法并入目录，也无法回到基因组上核对。
8. **边缘行。** offset ≤ 1 的行（E. coli 3，K. pneumoniae 5）是岛边界上的差异，更可能反映泡的范围不同，而不是嵌套插入。

## 结论

**现有结果不能并入目录。** 它只能说明"大岛内部可以找到嵌套 IS"这一思路可行，IS1 的信号是可信的。

如果要做，stage 32 需要重写：
- 按序列相似度（而不是长度桶）给停放岛配对，并考虑两个方向；
- 复用 Layer 2 的容错分解；
- 用 `canonical_insert_key` 作键；
- 输出序列和基因组坐标；
- 合并率对照 v3。

适用范围是第一轮加加深轮的全部停放泡。要不要做，由用户决定。
